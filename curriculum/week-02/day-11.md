# День 11 — Типовой обмен: исходящий, входящий, аннулирование

**Время:** 1,5–2,5 ч  
**Цель дня:** пройти happy-path обмена и зафиксировать точки, где пользователь «застревает».

## Теория

### Исходящий документ (отправитель)

1. Подготовка пакета (XML УПД / файл).  
2. Подписание КЭП (локально в 1С/браузере или по политике сервера).  
3. Передача в Диадок.  
4. Ожидание транспортных квитанций / статусов.  
5. Ожидание реакции контрагента (подпись, отказ, уточнение).

### Входящий документ (получатель)

1. Появление во входящих (веб / 1С по обмену).  
2. Просмотр / проверка подписи и реквизитов.  
3. Подписание ответного титула **или** отказ / запрос уточнения.  
4. Отражение в учёте (проведение).

### Аннулирование и корректировки

- **Аннулирование** — согласованная отмена уже отправленного/принятого (часто требует подписи обеих сторон — зависит от типа документа и регламента).  
- **Исправление / корректировочный документ** — не путать с аннулированием: для УПД/СФ есть свои типы.  
- Ошибка саппорта: советовать «просто удалить из 1С» без юридической процедуры на стороне ЭДО.

### Ответная подпись

Для двусторонних документов получатель ставит свою КЭП. Пока её нет — документооборот **не завершён**, даже если «файл у контрагента есть».

## Практика

### Вариант A — веб-кабинет Диадок

Пройдите (тестовый контур идеально):

1. Исходящий неформализованный документ (PDF) → подпись → отправка тестовому контрагенту / тестовой организации.  
2. Входящий: принять/подписать (или смоделировать второй учёткой).  
3. Найдите в UI действие аннулирования / отказа — выпишите точные названия кнопок и статусов.  
4. Снимите «скрин-конспект»: статус до и после каждого шага (в журнал текстом).

### Вариант B — без кабинета

1. По справке Диадок составьте **пошаговый сценарий** happy-path (12–20 шагов) для УПД.  
2. Отметьте шаги, где нужна КЭП.  
3. Добавьте ветки: отказ получателя; контрагент не принял приглашение; роуминг.  
4. Оформите как мини-инструкцию для L1 поддержки (полстраницы).
