# День 26 — Smoke и регрессия перед релизом

**Время:** 1,5–2,5 ч  
**Цель дня:** чеклист smoke для контура подпись → отправка → получение → проверка цепочки.

## Теория

### Зачем smoke для ЭДО

Релиз модуля 1С, обновление CSP, смена Chrome, выпуск нового формата УПД — всё это ломает «тихие» места. Smoke ловит катастрофу за 30–60 минут, не за неделю жалоб.

### Минимальный контур проверки

```text
1. Крипто на клиенте (или сервере — как в проде)
2. Подпись тестовых данных / тестового документа
3. Проверка подписи
4. Связь с оператором (auth)
5. Исходящий документ (лучше тест-контур)
6. Входящий / обновление статуса
7. Отображение в 1С
8. Негатив: просроченный/чужой сертификат отвергается ожидаемо
```

### Регрессия шире smoke

- разные браузеры;  
- токен и реестр;  
- роуминг-контрагент;  
- МЧД;  
- формализованный + неформализованный;  
- аннулирование;  
- права обычного пользователя (не админа).

Помечайте кейсы: *blocker / major / minor*.

## Практика

1. Создайте чеклист [`labs/smoke-edo-checklist.md`](../../labs/smoke-edo-checklist.md) — дополните под свою среду (уже есть каркас).  
2. Пройдите его надоступном стенде **или** отметьте каждый пункт: «как проверить без стенда / какой артефакт заменить».  
3. Добавьте раздел «перед обновлением CSP» из 8 проверок.  
4. Опишите gate: при каком результате релиз останавливаем.
