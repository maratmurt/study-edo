# День 23 — Логи и диагностика

**Время:** 1,5–2,5 ч  
**Цель дня:** разбор логов; шаблон тикета с нужными артефактами.

## Теория

### Где искать следы

| Компонент | Что смотреть |
|-----------|--------------|
| КриптоПро CSP | Журналы событий Windows, сообщения GUI, коды ошибок |
| Browser plugin | Консоль браузера (F12), текст исключения JS |
| 1С | Журнал регистрации, типовые ошибки ЭДО, технологический журнал (если включён) |
| Диадок | Текст ошибки модуля, id документа/сообщения, HTTP статус API |
| Сеть | HAR, прокси-лог, доступность OCSP/CDP |

### Как читать ошибку

1. **Где** возникла (клиент / сервер 1С / API).  
2. **Когда** (после обновления? смены сертификата?).  
3. **Код + текст** дословно.  
4. **Идентификаторы**: BoxId, DocumentId, MessageId, thumbprint (не ключ!).  
5. **Воспроизводимость**: один пользователь или все.

### Шаблон тикета (поля)

- Организация / ИНН  
- Среда (бой/тест), конфигурация 1С + версии  
- Версии: ОС, браузер, CSP, плагин, модуль ЭДО  
- Симптом + скрин  
- Шаги воспроизведения  
- Ожидание / факт  
- Идентификаторы документа  
- Уже проверенные пункты чеклиста  
- Вложения: логи (без секретов), HAR при сетевых проблемах  

## Практика

1. Создайте/заполните [`support-playbooks/ticket-template.md`](../../support-playbooks/ticket-template.md).  
2. Разберите **3 лога**:
   - возьмите свои из лаб **или** используйте синтетические примеры в [`labs/sample-logs.md`](../../labs/sample-logs.md);  
   - для каждого: класс сбоя, гипотеза, следующий шаг.  
3. Напишите один «идеальный» тикет по самому сложному из трёх случаев.
