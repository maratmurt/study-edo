# День 25 — Разработка: точки расширения

**Время:** 1,5–2,5 ч  
**Цель дня:** черновик ТЗ на небольшую доработку в контуре ЭДО.

## Теория

### Где обычно расширяют

| Точка | Примеры доработок |
|-------|-------------------|
| 1С: подписки на события ЭДО | Уведомление при ошибке отправки |
| 1С: регламентные задания | Ретрай, эскалация «висит > N часов» |
| 1С: формы документов | Подсказка статуса, кнопка диагностики |
| Backend рядом с Диадок API | Нормализация webhook/events |
| Веб-страница подписи | UX выбора сертификата, показ реквизитов |
| Мониторинг | Алерты по API errors / очереди |

### Хорошее ТЗ для ЭДО-доработки

Обязательные разделы:

1. Проблема и для кого  
2. Текущий процесс (as-is)  
3. Целевой процесс (to-be)  
4. Границы (что не делаем)  
5. Данные и идентификаторы  
6. Ошибки и ретраи  
7. Безопасность (секреты, ПДн, логи)  
8. Критерии приёмки + тест-кейсы  
9. Риски (форматы ФНС, лимиты API)

### Идеи на выбор для практики

**A.** Уведомление ответственным о документах без подписи > 24 ч.  
**B.** Автоматический ретрай отправки при временной ошибке сети/API (с лимитом).  
**C.** Кнопка «собрать пакет диагностики» (версии, thumbprint, последний error id).

## Практика

1. Выберите A, B или C.  
2. Напишите черновик ТЗ в `journal/day-25-tz.md` (1–2 страницы).  
3. Добавьте 5 тест-кейсов приёмки (включая негативные).  
4. Отметьте зависимости: CSP/плагин/Диадок/права 1С.

## Чеклист «Готово»

- [ ] ТЗ с разделами 1–9  
- [ ] ≥ 5 тест-кейсов  
- [ ] Границы scope зафиксированы  
- [ ] Учтены безопасность логов
