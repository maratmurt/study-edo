# День 22 — Каталог инцидентов

**Время:** 1,5–2,5 ч  
**Цель дня:** матрица «инцидент → симптомы → проверки → фикс» по всем классам сбоев курса.

## Теория

### Каталог как инструмент L1/L2

Хороший каталог:

- начинается с **слов пользователя** (симптомов);
- ведёт к **классам** (крипто / ЭДО / полномочия / формат / интеграция / сеть);
- даёт **упорядоченные проверки**;
- указывает **границу эскалации** и нужные вложения.

Без каталога каждый тикет расследуется с нуля.

### Области покрытия (минимум)

1. Сертификат / контейнер / лицензия CSP  
2. Плагин браузера  
3. Токен / RDP  
4. Приглашение / роуминг / ящик  
5. Обмен 1С ↔ Диадок  
6. МЧД / полномочия  
7. Формат УПД / реквизиты  
8. Сеть / прокси / TLS

1. Заполните матрицу в журнале (не меньше **12 строк**):

| ID | Симптом (слова пользователя) | Класс | Проверки (3–5) | Фикс / workaround | Эскалация |
|----|------------------------------|-------|----------------|-------------------|-----------|

2. Перенесите лучшие строки в playbooks:
   - [`support-playbooks/incident-catalog.md`](../../support-playbooks/incident-catalog.md)  
3. Для 3 инцидентов добавьте **негативный критерий**: «если вот это — вы на ложном пути».
