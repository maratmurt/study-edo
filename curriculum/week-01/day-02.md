# День 02 — ФЗ-63 и юридическая сила КЭП

**Время:** 1,5–2,5 ч  
**Цель дня:** знать, что даёт КЭП по закону и когда одного «файла с подписью» недостаточно.

## Теория

### Зачем закон, если есть криптография

Криптография доказывает: *эти данные подписаны ключом, соответствующим сертификату, и не менялись*.  
Закон отвечает: *можно ли считать это равным собственноручной подписи и при каких условиях*.

### Ключевые идеи ФЗ-63 (для инженера и саппорта)

1. **Электронная подпись** — информация в электронной форме, присоединённая к другой информации или иным образом связанная с ней, которая используется для определения лица, подписывающего информацию.
2. **Виды ЭП** — простая, неквалифицированная, квалифицированная (день 01).
3. **КЭП** признаётся равнозначной собственноручной подписи, если:
  - сертификат выдан **аккредитованным** УЦ;
  - использовано **сертифицированное** средство ЭП;
  - сертификат **действителен** на момент подписания (не истёк, не отозван);
  - соблюдены требования к формату и области применения (отраслевые правила).
4. **НЭП** приравнивается к собственноручной, если есть **соглашение** сторон или норма закона.
5. **ПЭП** — то же: нужна договорённость о признании.

### Что КЭП *не* решает сама по себе


| Ожидание пользователя                          | Реальность                                                                      |
| ---------------------------------------------- | ------------------------------------------------------------------------------- |
| «Подписал — значит документ принят налоговой»  | Нужен ещё правильный **формат** (УПД и т.д.) и канал (оператор / ИС)            |
| «Сертификат есть — могу подписать за компанию» | Нужны полномочия: должность в сертификате / **МЧД** / доверенность              |
| «Файл .sig лежит рядом — всё ок»               | Проверяющий должен уметь проверить цепочку и формат (CAdES и т.д.)              |
| «Вчера подписал — навсегда валидно»            | При долгосрочном хранении важны метки времени / архивные форматы (CAdES-T/XLT1) |


### Типовые кейсы

**УПД (универсальный передаточный документ)**  
Обычно: КЭП + обмен через оператора ЭДО + формат по требованиям ФНС. Подпись директора или уполномоченного с МЧД.

**Договор с контрагентом**  
Часто КЭП через оператора или согласованный порядок (иногда НЭП по соглашению). Важно: обе стороны принимают тот же вид ЭП и канал.

**Внутренний приказ**  
Может хватить ПЭП/НЭП по локальному регламенту компании. Для «внешнего» мира это не заменяет КЭП.

### Фраза для тикета поддержки

> Проверьте: (1) вид требуемой подписи, (2) действительность сертификата, (3) полномочия подписанта, (4) формат документа и канал доставки. Сбой в любом пункте выглядит как «подпись не принимается».

## Практика

1. В журнале (`journal/day-02.md`) напишите конспект **«Когда нужна КЭП»** — 8–12 тезисов своими словами.
2. Разберите три кейса (УПД, договор, внутренний приказ). Для каждого ответьте:
  - Какой вид ЭП минимально достаточен?
  - Нужен ли оператор ЭДО?
  - Какие 2 риска, если выбрать более «слабый» вид?
3. Сформулируйте ответ пользователю: «Почему мой сертификат физлица не подходит для УПД от ООО без доверенности?»
