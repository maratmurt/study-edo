# День 06 — КриптоПро на практике: CSP, носители, лицензии

**Время:** 1,5–2,5 ч  
**Цель дня:** собрать чеклист установки и воспроизвести классический кейс «сертификат есть — ключа нет».

## Теория

### Стек КриптоПро (минимум)

```text
Приложение (1С, браузер, cryptcp)
        │
        ▼
КриптоПро CSP  ←── лицензия
        │
        ├── контейнеры в реестре
        └── контейнеры на токене ←── драйвер токена
```

**CSP (Cryptographic Service Provider)** — криптопровайдер Windows API / интерфейс, через который приложения просят «подписать / захешировать / проверить».

### Носители

| Носитель | Плюсы | Минусы / риски |
|----------|--------|----------------|
| Реестр | Удобно на сервере/RDP | Легче скопировать; привязка к профилю Windows |
| Токен | Закрытый ключ не покидает устройство (в идеале) | Драйверы, пин, «не видит считыватель» |
| Облачная подпись | Без локального токена | Другая модель доверия и поддержки |

### Лицензии и версии

- Несовпадение версии CSP и плагина браузера — частый источник «раньше работало».  
- Несколько CSP (VipNet, КриптоПро) на одной машине могут конфликтовать.  
- Сервер 1С и клиент пользователя — **разные** места, где должна быть криптография (зависит от архитектуры: тонкий клиент / веб / серверная подпись).

### Кейс «сертификат есть, ключа нет»

Как получается:

1. Импортировали только `.cer` / `.p7b` в личные.  
2. Контейнер на токене, токен не вставлен / другой PIN / другой считыватель.  
3. Контейнер в профиле другого пользователя Windows / службы.  
4. Контейнер удалили, сертификат остался.  
5. Экспорт «без закрытого ключа» перенесли на новый ПК.

Диагностика (порядок):

1. Сертификат в «Личные»?  
2. Есть ли связанный контейнер (КриптоПро → «Протестировать» / просмотр ключей)?  
3. Носитель доступен текущему пользователю?  
4. Срок и цепочка ОК  
5. Лицензия CSP?

## Практика

### Вариант A — со стендом

1. Пройдите чеклист установки (запишите версии в журнал):
   - ОС;
   - КриптоПро CSP (версия, лицензия: да/нет/пробная);
   - токен/драйвер (если есть);
   - наличие тестового сертификата.  
2. Воспроизведите кейс «сертификат без ключа»:
   - экспортируйте сертификат **без** закрытого ключа;
   - на этой же или другой учётки импортируйте только `.cer`;
   - попробуйте подписать → зафиксируйте сообщение об ошибке.  
3. Верните рабочую связку сертификат+контейнер; убедитесь, что подпись снова возможна.

### Вариант B — без стенда

1. Составьте чеклист установки на 15 пунктов (до установки плагина браузера — он на неделе 3).  
2. Напишите скрипт разговора с пользователем на кейс «сертификат есть, подписать нельзя» (7–10 вопросов).  
3. Заполните playbook-черновик в журнале: симптом → проверки → фикс / эскалация.
