# День 03 — Хеш, асимметрия, ГОСТ и контейнер ключей

**Время:** 1,5–2,5 ч  
**Цель дня:** понимать, как из «данных + ключ» получается подпись; знать роль ГОСТ Р 34.10/34.11 и контейнера КриптоПро.

## Теория

### Хеш-функция

**Хеш** — короткое «отпечаток» данных фиксированной длины. Свойства для ЭП:

- одно и то же сообщение → один и тот же хеш;
- малейшее изменение файла → другой хеш;
- по хешу нельзя восстановить исходный файл.

Подписывают обычно не весь файл «как поток на глаз», а **хеш файла** (или структуру CMS, куда входит хеш).

В российском контуре часто: **ГОСТ Р 34.11-2012** (Стрибог), ранее — ГОСТ Р 34.11-94.

### Асимметричная криптография

- **Закрытый ключ** — только у владельца; им **создают** подпись.  
- **Открытый ключ** — в сертификате; им **проверяют** подпись.

Аналогия: закрытый ключ — печать, открытый — образец оттиска в паспорте печати.

Алгоритм подписи в РФ: **ГОСТ Р 34.10-2012** (эллиптические кривые). Встречаются параметры 256 и 512 бит.

### Схема подписания (упрощённо)

```text
Документ ──► Хеш (34.11) ──► Подпись хеша закрытым ключом (34.10)
                                      │
                                      ▼
                         Подпись + сертификат (открытый ключ)
                                      │
                                      ▼
Проверяющий: хеш документа + проверка подписи открытым ключом
             + проверка цепочки сертификата (день 04)
```

### Контейнер ключей КриптоПро

**Контейнер** — хранилище закрытого ключа (и связанных данных) в CSP:

- в **реестре** Windows;
- на **токене**/смарт-карте (JaCarta, Рутокен и т.п.);
- реже — файл на диске (зависит от продукта и политики).

Важно для поддержки:

| Симптом | Частая причина |
|---------|----------------|
| Сертификат виден, подписать нельзя | Нет контейнера закрытого ключа / другой пользователь Windows |
| После переустановки ОС «пропали ключи» | Контейнер был в старом профиле/реестре |
| На другом ПК сертификат есть из файла .cer | .cer — только открытая часть; закрытый ключ не переносится так |

**Сертификат ≠ закрытый ключ.** Сертификат можно экспортировать без ключа; для подписи нужен контейнер с закрытым ключом.

### Лицензия CSP

КриптоПро CSP — коммерческий продукт. Без лицензии часть функций ограничена (зависит от версии/режима). Для обучения используют пробный период / тестовые среды; на проде — рабочая лицензия.

## Практика

### Вариант A — есть КриптоПро CSP

1. Установите КриптоПро CSP (актуальный дистрибутив с сайта КриптоПро).  
2. Откройте оснастку управления: «КриптоПро CSP» → вкладки «Сервис» / просмотр контейнеров.  
3. Если есть тестовый сертификат УЦ — установите; найдите контейнер, запишите в журнал:
   - имя контейнера;
   - носитель (реестр / считыватель);
   - алгоритм (ГОСТ 2012 и длина).  
4. Объясните своими словами: что будет, если удалить контейнер, но оставить сертификат в хранилище.

### Вариант B — нет CSP (бумажная лаба)

1. В журнале нарисуйте схему: файл → хеш → подпись → проверка.  
2. Заполните таблицу «объект → где хранится»:

| Объект | Где обычно | Можно ли скопировать флешкой «как файл»? |
|--------|------------|------------------------------------------|
| Закрытый ключ в контейнере | | |
| Сертификат (.cer) | | |
| Отзыв (CRL) | | |

3. Прочитайте раздел про контейнеры в документации КриптоПро (ссылка ниже) и выпишите 5 пунктов «для саппорта».
