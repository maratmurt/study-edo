# День 20 — Безопасность веб-подписи

**Время:** 1,5–2,5 ч  
**Цель дня:** threat model на одну страницу; рекомендации для саппорта и разработки.

## Теория

### Главный риск

Если злоумышленник выполняет JS на странице подписи (XSS) или подменяет страницу (фишинг), он может заставить плагин подписать **вредоносное содержимое**, пока пользователь думает, что подписывает УПД.

Плагин снижает барьер доступа к ключу для **страницы**, которой пользователь доверяет. Доверие к origin критично.

### Модель угроз (кратко)

| Угроза | Вектор | Митигация |
|--------|--------|-----------|
| XSS → подпись | Внедрение скрипта | CSP headers, санитизация, Trusted Types |
| Фишинг | Поддельный сайт с тем же UX | Обучение, запрет ввода PIN на «левых» доменах, allowlist плагина |
| MITM | Подмена трафика | HTTPS, HSTS |
| Вредоносное расширение | Доступ к странице | Политики расширений в корпорации |
| Утечка подписываемых данных | Логи/аналитика | Не логировать тела документов и Base64 подписей целиком в открытых логах |
| Clickjacking | iframe поверх кнопки | `X-Frame-Options` / `frame-ancestors` |

### Content-Security-Policy (CSP headers)

Не путать с КриптоПро CSP!  
HTTP-заголовок **Content-Security-Policy** ограничивает, какие скрипты может выполнять страница — снижает риск XSS.

### Что можно / нельзя в вебе

**Можно:** инициировать подпись, показать сертификат, передать результат на свой backend.  
**Нельзя полагаться на:** «секрет в JavaScript», скрытый PIN, «подпись гарантирует согласие с тем, что пользователь не видел».  
**Нужно:** показывать пользователю **что именно** подписывается (сумма, контрагент, хэш/имя файла).

### Советы саппорту

- Не просите прислать закрытый ключ, контейнер или PIN в тикете.  
- Не советуйте отключать антивирус «насовсем» и ставить плагины с пиратских сайтов.  
- При подозрении на фишинг — остановите подписание, проверьте URL.
