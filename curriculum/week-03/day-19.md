# День 19 — Токены, драйверы и RDP

**Время:** 1,5–2,5 ч  
**Цель дня:** чеклист «не видит токен»; понимать отличия локальной работы и терминала.

## Теория

### Локальная цепочка токена

```text
USB-токен
  → драйвер производителя (JaCarta, Rutoken, …)
  → считыватель в ОС
  → КриптоПро CSP видит носитель
  → контейнер на токене
  → приложение / плагин
```

Сбой в любом звене = «нет сертификатов» или «ошибка носителя».

### Пин-код

- PIN токена ≠ пароль Windows ≠ пароль от кабинета Диадок.  
- Блокировка после N неверных попыток — частый срочный тикет.  
- Смена PIN и разблокировка — по регламенту админа/УЦ, не «угадывать».

### RDP / терминальный сервер

| Сценарий | Что происходит с токеном |
|----------|---------------------------|
| Токен вставлен в **локальный** ПК, сессия RDP на сервер | По умолчанию сервер **не видит** токен |
| Проброс смарт-карт в RDP | Иногда работает, часто хрупко (политики, драйверы на обеих сторонах) |
| Токен вставлен в **сервер** | Видят процессы сервера; неудобно и небезопасно для многих пользователей |
| Подпись на клиенте 1С (толстый/тонкий с криптой на клиенте) | Нужен токен/CSP на машине пользователя |
| Подпись на сервере 1С | CSP и контейнеры на сервере |

Правило: прежде чем чинить «плагин», спросите: **где выполняется подпись и где физически ключ**.

### Другие грабли

- Хаб USB без питания.  
- Два CSP конкурируют за считыватель.  
- Сертификат установлен в хранилище компьютера, а приложение смотрит пользователя (или наоборот).  
- RemoteApp + старая версия клиента RDP.

## Практика

1. Составьте чеклист «не видит токен» из 15 пунктов (от кабеля до CSP). Сохраните в журнал и дополните [`support-playbooks/token-not-seen.md`](../../support-playbooks/token-not-seen.md).  
2. Заполните сравнительную таблицу: локально vs RDP vs серверная подпись 1С — где должен быть CSP, где токен, где плагин браузера.  
3. Напишите скрипт разговора (8 вопросов) для тикета «в терминале не подписывается».  
4. Если есть токен — выполните: вставить → виден в CSP → тест контейнера → вынуть → повторить ошибку → вернуть. Зафиксируйте сообщения.
