# День 15 — Архитектура подписи в браузере

**Время:** 1,5–2,5 ч  
**Цель дня:** нарисовать sequence diagram и список точек отказа от страницы до носителя.

## Теория

### Зачем плагин / расширение

Браузер **не имеет** прямого доступа к закрытым ключам КриптоПро и токенам (и это правильно с точки зрения безопасности). Поэтому цепочка такая:

```text
Веб-страница (JS)
    → JS API (cadesplugin / аналог)
    → Расширение браузера + Native host / плагин
    → КриптоПро CSP
    → Контейнер (реестр / токен)
```

Пользователь видит одну кнопку «Подписать». Саппорт должен видеть **5 слоёв**.

### Sequence (успешный сценарий)

```text
User → Page: нажал «Подписать»
Page → JS API: создать объект подписи, выбрать сертификат
JS API → Plugin: вызов native
Plugin → CSP: найти контейнер, вычислить хеш, подписать
CSP → Token: (если нужно) PIN / операция на носителе
CSP → Plugin: CMS/CAdES (Base64)
Plugin → Page: строка подписи
Page → Server: отправить документ + подпись (или только подпись)
Server → Page: результат проверки / следующий шаг ЭДО
```

### Точки отказа (чек-лист мышления)

| Слой | Примеры сбоев |
|------|----------------|
| Страница | Смешанный контент HTTP/HTTPS, блокировка скрипта, неверный init |
| JS API | `cadesplugin` undefined, таймаут инициализации |
| Расширение | Не установлено, выключено, другая учётка Chrome |
| Native / плагин | Не установлен, не совпала версия с CSP |
| CSP | Нет лицензии, нет контейнера, неверный алгоритм |
| Носитель | Не вставлен, драйвер, PIN, RDP |
| Сервер | Ждёт другой формат/алгоритм, не проверяет ГОСТ |

### Почему «на другом ПК работает»

Другая версия Chrome + расширения, другой CSP, сертификат в другом профиле Windows, токен виден только локально, групповые политики, антивирус режет native messaging.

## Практика

1. В журнале нарисуйте **sequence diagram** успешной подписи (можно mermaid `sequenceDiagram`).  
2. Составьте список из **12 точек отказа** — привяжите каждую к слою.  
3. Для 4 точек напишите: *симптом в UI* → *что спросить* → *куда смотреть*.  
4. Ответьте: может ли сервер «подписать за пользователя» без его ключа в браузерном сценарии? Когда используют серверную подпись вместо браузерной?
